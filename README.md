# くじ番号メーカー (kuji-maker)

ロト6・ロト7・ミニロト・ナンバーズ3/4・ビンゴ5・toto・mini toto の数字をボタンひとつで選ぶWebアプリ。
公開先は **`https://kuji-maker.github.io/`**（HAKONIWA LAB とは別サイト）。

## なぜ HAKONIWA LAB と分けたか（2026-09-11）

hakoniwalab.com は AdSense の3回目の審査中で、ギャンブル関連ページを同居させたくない。
GitHub の同アカウントに新リポジトリを作ると自動的に `hakoniwalab.com/配下` になってしまうため、
**Organization `kuji-maker` を作って別ドメイン（`kuji-maker.github.io`）にした**。
Organization は同じ GitHub アカウントから作れるので、ログインもpushの認証設定もそのまま使える
（別アカウントを作ると [[feedback_github_pages_deploy_needs_token]] の GCM 2アカウント問題が再発する）。

github.io のままなので AdSense は貼れない。オモチャなので最初からそのつもり。

## このアプリがやらないこと

**予想をしない。** 数字選択式宝くじの抽せんは毎回独立していて、過去の出目から次回は当てられない。
「よく出る数字」「しばらく出ていない数字」は有限回なら必ず生じるばらつきで、次回とは無関係。
そのためコードのどこにも「当たりやすくする」処理は無いし、書けない。

**唯一、意味のある操作が「被りにくくする」こと。** 当せん金は同じ等級の当せん口数で山分けなので、
みんなが選ぶ並びで当たると取り分が減る。当たる確率は1ミリも変わらないが、分配は変えられる。
この区別はページ本文でも繰り返し書いている。

## 確率はハードコードしない

「約609万分の1」のような数字を手で書くと、写し間違えても誰も気づけない。
組み合わせの数は数学的に決まるので `combinations()` で出して表示する。検算済み:

| くじ | 全通り | 根拠 |
|---|---|---|
| ロト7 | 10,295,472 | C(37,7) |
| ロト6 | 6,096,454 | C(43,6) |
| ミニロト | 169,911 | C(31,5) |
| ビンゴ5 | 390,625 | 5^8（8マス×各5択） |
| ナンバーズ4 | 10,000 | 10^4 |
| ナンバーズ3 | 1,000 | 10^3 |
| toto | 1,594,323 | 3^13 |
| mini toto | 243 | 3^5 |

一方 **当せん金額は回ごとに変わるのでアプリでは扱わない**。みずほ銀行の公式へ誘導する。

## 「人と被りにくく」の中身

人が選びがちな形には、はっきりした傾向がある。いちばん大きいのは誕生日。

| くじ | やっていること |
|---|---|
| ロト6・ロト7 | 32以上に重み1.7、1〜12に0.8。**32以上が最低1つ入る**まで引き直す |
| ミニロト | 1〜12（月に使われる）に0.75、13〜31に1.3 |
| ナンバーズ | ゾロ目・階段（1234）・月日として読める並び（0325 など）を弾く |
| ビンゴ5 | 各マスで「何番目を選ぶか」がそろわないようにする（マークシート上で同じ形になるため） |
| toto | **何もしない**。試合を知らずに重みを変えるのは根拠のない味付けになる |

重みは 1.7 に落としてある。当初 2.2 にしたら合計値の平均が 133→177 まで飛び、
毎回あからさまに高い数字ばかりになった。1.7 なら 133→153 で、偏りすぎない。

判定の内訳（○×）は「人と被りにくく」を選んだときだけ画面に出す。何をしているか隠さない。

## 乱数

`crypto.getRandomValues` を使う。くじの番号を作る道具で「実は偏っていた」は避けたいので、
`Math.random` ではなく素性のはっきりした方にした。
「今日の数字」だけは xmur3 + mulberry32 の再現できる乱数で、
`生年月日|今日の日付|くじの種類` をシードにする。同じ日のうちは何度押しても同じ数字。

## 踏んだ落とし穴

1. **口数の select に無い値が入ると、無言で0口になって結果が空になった。**
   原因が分からない壊れ方なので `Math.max(1, Math.min(10, Number(v) || 1))` で丸めるようにした
2. **toto の試合ラベルを「第10試合」にしたら、幅34pxのマスで折り返して隣のマスに重なった。**
   番号だけの表示に変更（[[feedback_hidden_attr_loses_to_display]] と同じ、CSSで無言で壊れる系）

## 記事

差別化できるのは「自前で数えた数字」だけなので、引用ではなくその場で計算した値しか載せない。

| 記事 | 主題 | 数字の出どころ |
|---|---|---|
| `guide/loto-tosenkin-yamawake/` | 当せん金は山分け。**分配は変えられる** | 6,096,454通りの全列挙 |
| `guide/yoku-deru-suji/` | 出現回数の偏りは**公平な抽せんでも必ず生じる** | 2,000回×2,000セットのシミュレーション（乱数の種 20260912） |

2本目の主な結果（2026-09-12）:

- 2,000回で各数字の期待出現回数は279.1回。1位と最下位の差は**平均68.9回**（最小38・最大111）。
  差が50回未満だったのは2,000セット中32だけ → 差があること自体は偏りの証拠にならない
- 前半1,000回のトップ10が後半1,000回でもトップ10に残るのは**平均2.32個**。
  無関係な10個を選んだときの期待値 10×10÷43＝2.33個と一致 → 過去の順位に予測力はゼロ
- 連番を含む組み合わせは54.72%、前回の数字が1つ以上再登場するのは61.87%（どちらも組み合わせから直接計算）
- どの時点でも平均9.6個が「直近10回で出ていない」状態。長い不在は珍しくない

シミュレーションのコードは記事内に `<details>` で丸ごと載せてある。
**別ファイルで置かないのは、Pages の MIME 任せ（.py がダウンロードになる）とリンク切れを避けるため。**

## デプロイ

Organization `kuji-maker` の **`kuji-maker.github.io`** リポジトリに push し、
GitHub Pages（main・ルート）を有効化する。git のローカル設定は他と同じ方式:

```
git config --local user.name hakoniwa-lab
git config --local user.email 309971408+hakoniwa-lab@users.noreply.github.com
git config --local credential.https://github.com.username hakoniwa-lab
```

**global には設定しない**（salonsenbai-lab の identity と混ざるため）。
